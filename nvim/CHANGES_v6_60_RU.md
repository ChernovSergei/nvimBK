# WordVim Neovim Integrated v6_60

## Установка

Закройте Neovim, сохраните резервную копию его конфигурации и распакуйте архив
в ту же папку конфигурации, заменив файлы. Используется прежний init.lua проекта.
Рабочие документы менять не нужно.

## Цвета стилей — настройка приложения

Panel color HEX в редакторе стиля теперь действует на все документы.
Enter на этом поле открывает палитру, Ctrl+s сохраняет цвет приложения.
Обе колонки во всех открытых документах обновляются сразу. Цвет привязан к имени
стиля, а не к номеру в правой колонке, порядку стилей или пути DOCX.
Автоматические цвета тоже одинаковы для одинаковых имён стилей.

Палитра хранится в stdpath('state')/wordvim/panel-colors.json, сохраняется между
запусками и применяется к новым документам. Отдельные установки Neovim в Windows
и WSL имеют собственные каталоги настроек приложения.

При первом чтении без общей палитры импортируются старые настройки v6_59.
Если один стиль раньше получил разные цвета в разных документах, выбирается
значение из наиболее недавно изменённого файла настроек. Общая палитра записывается
при следующем сохранении цвета. Пустое поле / Automatic сбрасывает цвет стиля
для всего приложения. Старые файлы настроек не удаляются.

Изменение только цвета колонок НЕ меняет DOCX и не включает его индикатор [+].
Color HEX (цвет текста), шрифт и другие свойства Word-стиля остаются свойствами
документа; их, как и раньше, нужно сохранить через :w.

## Содержание help

F1 открывает справку с оглавлением. В DOCX доступны также ссылки на подразделы:
абзацы, форматирование, списки, стили, страницы, таблицы, изображения и другие.

- j/k или стрелки — выбрать строку.
- Tab / Shift+Tab — следующий / предыдущий пункт оглавления.
- Enter или двойной щелчок по пункту — перейти к разделу.
- Backspace или gO — вернуться к оглавлению.
- 1 / 2 / 3 / 4 — сразу открыть соответствующую часть справки.
- q, Esc или F1 — закрыть справку и вернуться к работе.

Оглавление работает и при открытии help из запроса текста ячейки; введённый текст
сохраняется. Размер справки следует за рабочей областью Neovim.

## Shift+Enter: исправление передачи клавиши

Обработчик разрыва строки в Neovim сохраняется, добавлена поддержка Shift+Enter
на цифровом блоке. Для разрыва строки используйте Insert mode.
Обычный Enter продолжает создавать отдельный абзац.

Если Windows Terminal передаёт Shift+Enter как обычный Enter, Lua-сочетание не
может восстановить потерянный Shift. Поэтому добавлена команда настройки терминала:

    :WordTerminalSetup

Она назначает Shift+Enter последовательность ESC [ 13 ; 2 u, создаёт резервную
копию settings.json и сохраняет остальные настройки. После команды перезапустите
Neovim. Настройка относится к Windows Terminal и действует также на другие
приложения внутри этого терминала. Обычный Enter не меняется.

Если найдено несколько конфигураций терминала или путь нестандартный, откройте
Windows Terminal → Settings → Open JSON file и передайте показанный путь:

    :WordTerminalSetup C:/полный/путь/settings.json

Из PowerShell можно выполнить скрипт напрямую:

    powershell -NoProfile -ExecutionPolicy Bypass -File ./tools/Enable-ShiftEnter.ps1 -Apply

Без -Apply скрипт только показывает план изменений. Для нестандартного пути:
добавьте -SettingsPath "C:/полный/путь/settings.json". При запуске команды из
Neovim в WSL используется powershell.exe и перевод пути через wslpath.
Реальные пользовательские настройки терминала при сборке архива не изменялись:
их файла в среде выполнения не найдено.

Для проверки нажмите Shift+Enter после команды:

    :WordKeyCheck

Если получен <CR> без модификатора Shift, терминал передал обычный Enter.
Если получен <S-CR>, повторите тест в Insert mode. Диагностика не меняет документ.
Запасное сочетание для любого терминала: Ctrl+g, затем Enter.

Документация Windows Terminal по sendInput:
https://learn.microsoft.com/en-us/windows/terminal/customize-settings/actions#send-input
Документация установленного Neovim: :help tui-input и :help tui-csiu.

## Проверки сборки

Выполнены тесты реального Neovim:

    nvim --headless -n -u NONE -i NONE -l tests_global_help.lua
    nvim --headless -n -u NONE -i NONE -l tests_help_modes.lua
    nvim --headless -n -u NONE -i NONE -l tests_application_colors.lua
    nvim --headless -n -u NONE -i NONE -l tests_terminal_keys.lua
    nvim --headless -n -u NONE -i NONE -l tests_image_percent.lua

Проверены переходы оглавления, четыре контекста, ввод ячейки, возврат в Insert
и терминал; общая палитра в двух документах с разными списками стилей, её
сохранение и импорт старых цветов; отсутствие изменений DOCX при смене цвета.

В tests_terminal_keys.lua последовательность Shift+Enter передаётся реальному TUI
Neovim как байты терминала, а не как заранее распознанная клавиша через RPC.
Проверено: First line + Shift+Enter + Second line + Enter + New real paragraph
образуют один абзац с разрывом строки и один отдельный абзац по метаданным редактора.
Физическая клавиатура пользователя и полный DOCX round-trip через Pandoc/Word
в этой среде не проверялись. Для PowerShell-скрипта проверены JSON с комментариями,
сохранение посторонних сочетаний, резервная копия и повторное применение без дублей.
