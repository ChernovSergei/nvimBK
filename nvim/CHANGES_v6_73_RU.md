# WordVim v6.73 — изменения и использование

Обновление подготовлено в архиве конфигурации. Оно не устанавливается в действующий Neovim автоматически.

## Установка

Закройте Neovim. Сохраните копию действующей папки конфигурации и перенесите файлы архива в неё с заменой:

- Windows: `%LOCALAPPDATA%\nvim`.
- Linux и Linux внутри proot: `~/.config/nvim` (или `$XDG_CONFIG_HOME/nvim`).

Не заменяйте папку `nvim-data`. Перезапустите Neovim. F1 открывает справку с отдельными подразделами Neo-tree, Telescope, языковых серверов, дополнения кода и отладчика.

## Java

- `Space j r` или `Space r n`: переименовать класс, метод или переменную под курсором через JDTLS. При переименовании класса файл перемещается в той же папке пакета; изменённый переименованный файл записывается. `:wa` сохраняет изменения в остальных файлах. Уже существующий файл назначения или перенос класса в другую папку отклоняется. Старые дубликаты, созданные предыдущей версией, автоматически не удаляются.
- `gcc`: включить/выключить комментарий текущей строки. Для нескольких строк: `V`, выделить строки с `j/k`, затем `gc`.
- `Space f`: форматировать код. Форматирование также выполняется при сохранении; тайм-аут увеличен до двух секунд. Используется google-java-format с отступом четыре пробела, при недоступности — LSP. `:ConformInfo` показывает доступность. Форматтер нормализует отступы и пустые строки по своему стилю, но не исправляет ошибки Java и не удаляет содержимое строковых литералов. Это не точная копия форматтера IntelliJ.
- Новый пустой `.java` при открытии получает `public class Имя {}` и package из пути `src/main/java` или `src/test/java`. Для иных корней исходников package нужно указать вручную. `:JavaClass` вызывает генератор для пустого буфера. `package-info.java` и `module-info.java` не изменяются.
- Диагностика отображается во время ввода, а изменения передаются JDTLS с задержкой 150 мс. Фактический момент появления сообщения зависит от сервера и импорта проекта. `:WordJavaStatus` проверяет подключение; ошибки типа переменной не требуют запуска Maven.
- В Neo-tree `zO` раскрывает подпапки выбранной папки, `zM` сворачивает. Исправлен конфликт с немедленным выполнением `z`; включать `modifiable` у дерева не нужно.

В разделах F1 для PowerShell и Linux добавлены создание Maven/обычного Java/Node.js проекта, запуск, тесты и команды wrapper. Требуются JDK/Maven или Node/npm в PATH. Maven, встроенный в IntelliJ, не добавляется в PATH автоматически.

## DOCX и списки

Исправлена обработка временной ZIP-копии, включая документы Apache POI с ZIP64-дескрипторами. Исходный файл при открытии не меняется. Исправлена обработка нескольких таблиц в PowerShell 5.1.

Для ускорения открытия WordVim больше не запускает отдельные проверки списков, отступов и полей, если этих элементов нет в документе. Копирование файла для чтения отступов выполняется без запуска PowerShell. На тестовом simple.docx измерено около 5,8 с вместо 9,6 с при одинаковом PowerShell 7; с Windows PowerShell 5.1 — около 3,7 с. Это измерения конкретного небольшого файла, не гарантия для больших документов.

- Нумерация обновляется после обычного редактирования и выхода из Insert mode.
- `:WordListRenumber` — обновить сразу.
- `Alt+↑` / `Alt+↓` в Normal mode или `:WordListMoveUp` / `:WordListMoveDown` — переставить пункт вместе с его подпунктами. Команды действуют внутри одного уровня списка.

## Таблицы и вставка

В `:WordTable` отображаются номера стилей внутри ячеек и легенда справа:

1. normal
2. header
3. bold
4. italic
5. accent
6. warning
7. note

Это семь стилей ячеек WordVim, а не номера всех именованных стилей Word. Нажмите `1`–`7` в выбранной ячейке либо Enter и введите номер. Текст ячеек редактируется в основном DOCX-буфере. В редакторе доступны структура, объединение, границы, добавление и удаление строк/столбцов. `W` применяет изменения, `q` отменяет. На узком экране столбцы прокручиваются при перемещении `h/l`, чтобы легенда оставалась видимой.

- `:WordTableCopy` — скопировать таблицу под курсором вместе со стилями, границами и объединениями.
- `:WordTablePaste` — вставить копию после текущей строки или текущей таблицы; работает между открытыми DOCX в одном Neovim.
- `Space w p` / `:WordPaste` — вставить внешнее содержимое буфера обмена. Вставка происходит после строки/таблицы под курсором.
- `:WordInsertFile C:/path/file.docx` — вставить содержимое DOCX; также поддерживаются HTML и изображения PNG/JPEG/GIF/BMP/WebP.
- Обычный `Ctrl+v` по-прежнему вставляет текст.

Windows использует HTML/изображение/текст из системного буфера. Linux использует `wl-paste` или `xclip`, если доступен графический буфер; иначе — текстовый провайдер Neovim. В proot доступ к Android rich clipboard не гарантирован: для таблиц и изображений используйте экспорт в файл и `:WordInsertFile`.

Внешние таблицы импортируются с объединениями (до 50 строк и 20 столбцов). Вложенные таблицы не поддерживаются. Шрифты, сложное оформление, произвольные заливки и границы внешнего документа не гарантируются; WordVim использует свою модель таблиц и Pandoc. Картинки копируются во временное медиа-хранилище и включаются в DOCX при `:w`.

## Проверки и границы проверки

Проверены временные Java-файлы (переименование, сохранение, защита другого каталога), шаблон класса, перенумерация с сохранением меток абзацев, перемещение пунктов, отложенный ввод `z` затем `O` в немодифицируемом буфере, навигация по таблице и числовые стили, справка и существующие Java-сочетания.

Проверены копия пользовательского simple.docx в PowerShell 5.1 и 7, полноценный DOCX roundtrip, внешние HTML/изображение/DOCX и внутреннее копирование таблиц. Проверка Windows-ветки буфера использует имитацию содержимого, не изменяет личный буфер обмена.

Живой JDTLS и графический буфер сторонних приложений не проверялись. Linux/proot проверялись моделированием выбора платформы и зависимостей; физического запуска на Android не было.
