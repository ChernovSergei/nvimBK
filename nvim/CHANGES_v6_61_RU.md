# WordVim v6_61 — запуск Java в Windows

Исправлен выбор каталога конфигурации JDTLS: в Windows используется config_win,
в Linux — config_linux, в macOS — config_mac. Ранее в Windows выбирался Linux-каталог.

Добавлена проверка наличия единственного launcher JAR и доступного java.
Рабочий каталог JDTLS теперь содержит хеш полного пути проекта: одноимённые
проекты не делят служебные данные. Старые каталоги не удаляются.
Неустановленные расширения отладки/тестов больше не добавляют пустые пути в bundles.
Добавлены маркеры Gradle Kotlin DSL при поиске корня проекта.

Установка: закройте Neovim, сделайте резервную копию конфигурации и замените
файлы содержимым архива. В нём сохранены изменения v6_60.
Для минимальной замены достаточно ftplugin/java.lua и lua/plugins/java_launch.lua.
После перезапуска откройте Java-файл. Если JDTLS не установлен, установите его
через :Mason. Если выводится ошибка launcher JAR, переустановите пакет jdtls.

JDTLS требует современную Java (в текущей документации минимум Java 21),
при этом версия Java проекта может отличаться. По умолчанию используется
JAVA_HOME/bin/java, если доступен, иначе java из PATH. Для явного выбора JDK
добавьте перед загрузкой Java-файла в init.lua:

    vim.g.wordvim_java_cmd = "C:/Program Files/Java/jdk-21/bin/java.exe"

Замените путь на существующий путь вашего JDK.
Документация JDTLS: https://github.com/eclipse-jdtls/eclipse.jdt.ls

Проверки: tests_java_launch.lua проверяет выбор платформы Windows/Linux/macOS/ARM,
раздельные рабочие каталоги, launcher и отсутствие пустых путей расширений.
Синтаксис Lua проверен. Сам установленный у пользователя JDTLS не запускался.
Журнал lsp.log остался недоступен даже после предоставления разрешения;
точная причина конкретного завершения с кодом 1 не подтверждена журналом.
Если ошибка останется, скопируйте последние строки lsp.log в сообщение.
